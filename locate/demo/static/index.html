DINOv3 的 CLS 注意力图是怎么来的

页签① 的热图、红框和"25% token"用的都是它。它不是分割模型的输出，只是把 ViT 内部本来就有的一个量画了出来。

1. CLS token 是什么

ViT 把图切成 784 个 patch，每个变成一个 token；序列最前面再拼一个不对应任何像素的 CLS token，它的任务是把全图"汇总"成一个向量，输出头就接在它上面（DINOv3 还多拼了 4 个 register token，作用见第 4 条）。

这里的 CLS 是 DINOv3 自己的。整条流程有两个 ViT：冻结的 DINOv3（定位器，从没见过 NABirds 的标签）和我们在 NABirds 上微调的 ViT-B/16（分类器）。热图、框、挑 token 用的全是前者内部的注意力；分类器只负责接收裁剪图或被挑出的 token，它自己的注意力不参与。

2. 注意力权重本来就在那里

Transformer 每一层里，每个 token 都算出 query、key、value 三个向量；token i 对 token j 的注意力 = softmax_j(q_i · k_j / √d)。CLS 那一行就是"CLS 在汇总全图时从每个 patch 拿了多少"——784 个非负数，加起来正好是 1。

我们做的只是：取最后一层、12 个注意力头取平均、去掉 CLS 和 register 自己那几列，把剩下的 784 个数排回 28×28。再做一次 3×3 平滑、按最大值归一化，就是页签① 的热图。代码在 locate/dino_attn.py，四十来行。

3. 为什么它亮的地方就是主体

CLS 要给出一个能代表"这张图是什么"的向量。DINO 的训练方式（学生只看一小块裁剪、老师看整图，要求两边输出一致）逼着它把权重放在决定类别的地方——对细粒度图片来说就是那只鸟，而不是树枝和天空。没有任何标注告诉过它"鸟"在哪，这是训练目标的副产品。

4. 为什么 DINOv3 的图特别干净：register

老版本 ViT 有个毛病：训练久了会把几个背景 patch 当"草稿纸"，往里堆很大范数的全局信息，CLS 的注意力被这几个 patch 大量吸走（attention sink），热图上出现和内容无关的亮点。DINOv3（以及 DINOv2 + reg4）额外加了 4 个 register token 专门当草稿纸，patch 就不用再背这个包袱，CLS 的注意力只剩真正的内容。页签② 里 DINOv2 的 PCA 图背景有椒盐碎点、DINOv3 没有，是同一件事的另一种表现。

5. 和页签② 的黑白 mask 有什么区别

CLS 注意力（页签①）NCut 前景 mask（页签②）
看的是一个 token（CLS）的视角：它在看哪patch 之间谁和谁像：在相似度图上切一刀
怎么算一次前向顺手就有，几乎免费要解一个 N×N 的特征值问题
倾向亮在最有判别力的部位（头、翅斑），松一点的框刚好包住整只鸟圈出内部最一致的一整团，边界更贴

它不是分割，也不会永远对。画面里有比鸟更"显眼"的东西（一朵花、一辆卡车、一只松鼠）时，注意力会被带走，框就错了——NABirds 里约 4% 的图是这样。

页签② 的图怎么看

ViT 把图切成 N×N 个小方块（patch），每块输出一个 384 维向量，意思是「这一块是什么」。下面两张图都是从这些向量算出来的。

彩色图：模型给每一小块打的「标签」

384 维画不出来，用 PCA 找方差最大的 3 个方向当 R、G、B。

读法只有一条：颜色相近 = 特征相近 = 模型认为这两块是同一类东西。
  • 颜色本身没意义——每个模型自己做 PCA，DINOv2 的紫和 DINOv3 的绿不能对着比。要看的是边界干不干净、同一物体内部颜色统不统一。
  • 背景里的椒盐碎点 = 相邻两块明明是同一个东西，特征却差很多。这就是「邻域相似度」低在图上的样子。

黑白图：模型自己圈出的「主体」

白色 = 在模型特征看来自身最一致、和其余部分最不像、又不贴着画面边缘的那一团。全程没有任何标注。

算法叫 Normalized Cut（Shi & Malik 2000；用在 DINO 特征上是 TokenCut, CVPR 2022）：每个 patch 是一个点，两点之间的边 = 特征余弦相似度；找一条切断边最细的线把点分成两组，并用「切断的 ÷ 各组自己的总连接」惩罚太小的块；精确解是 NP-hard，实际解特征值问题 (D − W)v = λDv 取第二小特征向量的符号；两组里碰画面边界少的算前景。

邻域相似度每个 patch 和上下左右邻居的平均余弦相似度。越高特征越平滑，彩色图里碎点越少。
cos 相似度中位数全图 patch 两两有多像。DINOv2 ≈ 0.2、DINOv3 ≈ 0.6——所以 NCut 的阈值必须按每张图自适应（取中位数）。
前景占比白色块占全图比例。一只小鸟占 60% 肯定是切错了。
不是「DINO 认为这块是主体」——DINO 只提供「谁和谁像」这张网，圈哪块是 NCut 决定的。不是「最特别的」，也不是「面积最大的」。只切一刀，多个物体会合并或只留一个；小目标 patch 太少会吃亏。
